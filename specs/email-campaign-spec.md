# Email Campaigns Functionality Specification

This document details the end-to-end functionality of the "Email Campaigns" feature across the Tesla Parts projects. This feature enables administrators to create, manage, and dispatch bulk or targeted emails to registered customers and custom email addresses.

---

## 1. Backend Implementation (`tesla-parts-backend`)

The backend is responsible for storing mailing lists, aggregating recipient data securely, and offloading the heavy lifting of SMTP dispatch to background threads to ensure the API remains responsive.

### 1.1. Data Models (`models.py`)
- **`EmailList` Model**: Represents a saved group of users for recurring campaigns.
  - `id`: Primary key.
  - `name`: The display name of the list.
  - `created_at`: Timestamp.
- **`CustomerEmailListLink` Model**: A junction table (`customer_id`, `email_list_id`) establishing a many-to-many relationship between `EmailList` and `Customer`.

### 1.2. API Endpoints (`routers/email_campaigns.py`)
All endpoints in this router are protected by the `get_current_admin` dependency.

- **List Management**:
  - `GET /lists`: Retrieves all `EmailList` records. Crucially, as it pulls the related `Customer` records, it securely decrypts their PII (email, first name, last name) on the fly using `services.crypto.decrypt_value` before returning the JSON payload.
  - `POST /lists`: Creates a new `EmailList`. It accepts a name and an optional array of `customer_ids`, automatically generating the junction records in `CustomerEmailListLink`.
  - `DELETE /lists/{list_id}`: Deletes a specific email list.
  
- **Campaign Dispatching**:
  - `POST /lists/{list_id}/send`: 
    - Takes a `subject` and `body`.
    - Retrieves all customers linked to the list, decrypts their email addresses, and verifies the list is not empty.
    - Uses FastAPI's `BackgroundTasks` to asynchronously pass the recipient list to the `send_bulk_emails` helper function, returning a success response to the admin immediately.
  - `POST /send-direct`:
    - Takes a `subject`, `body`, an optional list of `customer_ids`, and an optional list of raw `emails` (strings).
    - It aggregates and decrypts emails for the provided customer IDs, combines them with the raw email strings, deduplicates the final list using a Python `set`, and dispatches the task to `BackgroundTasks`.

### 1.3. Email Engine (`services/email.py`)
- The `send_bulk_emails` background task iterates over the recipient list and calls `email_service.send_custom_email()`.
- **`send_custom_email`**:
  - Connects to `smtp.gmail.com` using standard `smtplib` and `MIMEMultipart`.
  - Sends the raw HTML `body` provided by the admin.
  - If SMTP credentials are missing from the environment, it gracefully fails by logging the intended output to the console, ensuring development environments don't crash.

## 2. Admin Frontend (`tesla-parts-admin`)

The admin interface (`components/EmailCampaigns.tsx`) provides a dual-tabbed dashboard for managing campaigns.

### 2.1. "Mailing Lists" Tab (Списки розсилки)
- **Dashboard View**: Displays saved email lists as cards detailing the list name, internal ID, and member count. 
- **Creation UI**:
  - Admins can click "Create List" to open a modal.
  - The modal provides a real-time, searchable list of all registered customers (filtering by name or email).
  - Admins toggle checkboxes to add users to the new list and save it.
- **Campaign Launch Modal**:
  - Clicking "Send" on a list card opens a modal.
  - Admins input the HTML/Text `Subject` and `Body`.
  - Submitting the form calls `api.sendCampaignToList`, triggering the backend background task, and updating the UI with a success notification.

### 2.2. "Direct Mailing" Tab (Пряма розсилка)
- Designed for ad-hoc, one-off campaigns without permanently saving a list.
- **Form Interface**:
  - Inputs for `Subject` and `Body`.
  - **Manual Email Entry**: A textarea allows admins to paste comma-separated or newline-separated custom email addresses.
  - **Customer Selection**: A searchable customer picker (identical to the list creation UI) allows admins to pick registered customers on the fly.
  - Submitting calls `api.sendDirectCampaign` with the combined custom emails and selected `customer_ids`.

---

## 3. Customer Frontend (`tesla-parts-shop`)

- **No Implementation**: The email campaign functionality is strictly an administrative tool. 
- The customer application itself does not possess any views or UI related to this feature. Customers interact with this system entirely passively by receiving the emails generated by the admin dashboard.
